# Limitations — what this repository does not do

A tool that does not say what it cannot do is asking to be misused. This page is the list of
things you should **not** expect from `kinetics`, with the reason and, where possible, the
measurement that shows the size of the gap.

## What the package cannot do at all

| Not supported | Why not | What to do instead |
|---|---|---|
| **Global fitting** — one Vmax/Km shared across several datasets or mutants | The fitting layer takes one `(S, v)` pair; sharing parameters needs a joint residual function | Write the joint residual with `scipy.optimize.least_squares`; use `fit_nonlinear` for the per-dataset version as a check |
| **Substrate inhibition** (v falls at high [S]) | Not in `INHIBITION_MODELS`; it has a different functional form | Fit `v = Vmax·S / (Km + S + S²/Ki)` yourself; the parameter guards in `models.py` show the idiom |
| **Robust loss functions** (Huber, Tukey) | `curve_fit` is least squares; robust losses change the objective and therefore the AICc | Consider them when one point dominates the residuals; say so in the methods if you do |
| **Errors in x** (uncertain substrate concentrations) | Least squares assumes x is exact | For dilution series this is usually negligible; for stopped-flow it is not, and you need an errors-in-variables model |
| **Time-course fitting** (progress curves) | Every function here takes initial rates | Progress-curve analysis integrates the rate equation; different problem |
| **Units checking** | Units are *declared* in the metadata and printed in reports, not enforced | Convert before you fit, and state the unit in the methods sentence |
| **Multiple substrates, cofactors, pH or temperature models** | Out of scope by design | — |
| **Non-parametric or Bayesian uncertainty** | Only asymptotic SEs and a percentile bootstrap | If you need a posterior, use PyMC/Stan; the bootstrap here is a fast sanity check |

## Where the package works but the answer may still be wrong

These are the dangerous cases, because nothing fails — you get a number.

### 1. The model is wrong, and no diagnostic here can tell you

Vmax = 9.98 ± 0.11 with R² = 0.99742 on a clean Michaelis–Menten dataset looks exactly like
Vmax = 9.98 ± 0.11 on a dataset generated by a Hill model with n = 0.99 — because those two
models are the same model at n = 1. The package reports what the data support *among the
models it was given*. It cannot invent the mechanism you did not consider.

**Measured example:** `datasets/sample/cooperative_hill.csv` is genuinely sigmoid (Hill
n = 2.039 ± 0.112). Fitting Michaelis–Menten to it is not refused; the AICc comparison
(ΔAICc = 26.97 in favour of Hill) is what tells you, and only if you ask for the comparison.

### 2. The design cannot answer the question

`datasets/sample/inhibition_weak.csv` returns a "best" mechanism that is **not** the true one,
with ΔAICc = 0.48 between the top two models and 1.68 to the third. The fit is not broken —
the experiment is. The package reports the ranking and prints the caveat, but a reader who
wants a mechanism will find one in the table.

**Rule of thumb:** if ΔAICc < 2 between mechanisms, the correct sentence is "indistinguishable
on these data", not the name of the winner.

### 3. Weighting is a modelling decision, and it changes the answer by a lot

The same seven calibration standards give an LOD of **0.109296** weighted by replicate SD and
**6.357793** unweighted — a factor of 58.17 (see
[Practical 4](practicals/practical-04-weighting-a-calibration.md)). Both are "the LOD". The
package selects weighting automatically when an `sd` column exists, prints `weighted True` and
the σ it used, and stops there. It cannot tell you whether your `sd` column means what the
LOD formula assumes it means.

### 4. Standard errors are optimistic when the model is nonlinear

The asymptotic standard errors from `curve_fit` assume the parameters are locally linear in
the data. On `michaelis_menten.csv` the normal-theory 95 % interval for Vmax
(9.774 – 10.193) is narrower at the upper end than the bootstrap interval
(9.7095 – 10.2630). The bootstrap is the one to report when the two disagree, and they will
disagree more as the data get thinner.

### 5. Replicates are not independent evidence

Fitting 27 rows and bootstrapping them gives a Vmax interval of width 0.554; bootstrapping the
9 means gives width 0.690. Tripling the rows bought a 20 % narrower interval, not the 42 % that
independence would predict, because the replicates estimate within-condition noise, not
between-condition error. Nothing in the package warns you about this: resampling rows is what
`bootstrap_ci` does, and it does it faithfully.

### 6. AICc is only comparable on the same response data

`FitResult.aicc` is a number. It is meaningful when two models are fitted to the same `v`. It
is **not** meaningful when:

* one fit is on `v` and another on `1/v` (the linearisations — the report prints
  "not comparable" for exactly this reason);
* the two fits used different numbers of rows (27-point AICc −97.06 vs 9-point AICc −40.13 is
  not evidence that the first is better);
* the two fits used different weighting (AICc assumes a single σ).

### 7. The bootstrap does not model systematic error

Every interval here resamples the points you have. A miscalibrated pipette, an unstable
temperature or a drifting detector is present in every resample, so its contribution vanishes
from the interval. The bootstrap answers "how much would this estimate move if I repeated the
experiment the same way?" — not "how wrong could this be?".

## Limits of this repository as a teaching resource

* **All data are simulated.** Every CSV carries `synthetic: true`, the generating seed and the
  error model, and `scripts/check_data_metadata.py` enforces both. The numbers are realistic;
  the *mess* of real data — baseline drift, lost time points, a cuvette with a bubble — is not
  represented.
* **No enzyme is named as a case study.** Nothing here tells you whether your enzyme follows
  Michaelis–Menten; that is a question about your protein.
* **Python 3.10+ only.** The package uses `X | None` annotations and `match`-free but modern
  typing; there is no compatibility shim for 3.9 or below.
* **The reference checker needs the network.** Offline, `--offline` verifies internal
  consistency only, and says so.
* **The documentation numbers are bound to the committed data.** If a dataset is regenerated,
  the modules that quote its numbers become wrong — which is why `make_figures.py --check` and
  `check_data_metadata.py` exist, and why both run in CI.

## What to do when this list bites you

1. Check whether the answer you are getting is one the design can support — read the ΔAICc and
   the standard errors before the point estimates.
2. State the model, the weighting and the σ definition in the methods. Most of the failure
   modes above happen because those three were left implicit.
3. Report the interval you would defend, and the version of the analysis you would want with
   more data. Both are results.
