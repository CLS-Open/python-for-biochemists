# Roadmap

This repository is number 2 of the 15 in the CLS-Open series, and the first one with numerical
dependencies. What follows is honest about the difference between *shipped*, *wanted* and
*deliberately refused* — the third list is the longest, because the whole point of the course
is knowing what a fit cannot tell you.

## Shipped in 0.1.0

| Component | State |
|---|---|
| `kinetics` package — models, fitting, linearisations, inhibition, calibration, reporting, CLI | complete, 100 % statement coverage, 206 tests |
| Six modules, five practicals, quiz and instructor pack | complete |
| Eight simulated datasets with SHA-256-verified metadata | complete, 115 rows |
| Four figures, every displayed number recorded in `figures/figure_values.json` | complete, reproduced by `make_figures.py --check` |
| Executed notebook (`01_fitting_decisions.ipynb`) | complete, re-executed in CI |
| Validation against independent SciPy implementations | 83 comparisons |
| DOI verification of every citation | 22/22 titles matched at Crossref |

## Wanted, in rough order of usefulness

These are not promises. They are the things a learner or teacher would plausibly need next,
listed so that a contribution has somewhere to go.

1. **A notebook per module.** Currently one notebook covers the fitting decisions; Modules 3–6
   would each benefit from an executable companion. The infrastructure (`check_notebooks.py`)
   already re-executes every notebook in CI, so adding one is cheap and self-verifying.
2. **Global fitting**, i.e. one Vmax/Km shared across several datasets. The most requested
   feature in every kinetics course, and the one that most often produces silently wrong
   parameters when done with per-dataset fits followed by averaging.
3. **Substrate inhibition** as a first-class model. The forward function is three lines; the
   work is in the datasets, the module text and the design advice (which [S] range reveals it).
4. **Robust regression** (Huber loss) with the AICc consequences spelled out rather than
   glossed.
5. **An errors-in-x example**, even a small one, because the assumption that [S] is exact is
   invisible until someone shows it failing.
6. **A worked "reanalyse this published figure" exercise**, using a digitised dataset from a
   paper. This is the single best way to teach that real data are messier than simulated data;
   it needs a dataset whose licence permits redistribution.

## Deliberately refused

Each of these has been considered and rejected, with the reason recorded so the decision can
be argued with rather than rediscovered:

| Refused | Reason |
|---|---|
| A mixed-inhibition (`α`) fit in `compare_inhibition_models` | With α free, the other three mechanisms are special cases, so it always wins on fit and costs more AICc than it buys. Offered as a forward model instead, with the responsibility left to the user (Module 6) |
| Silent row filtering (dropping non-positive rates, outliers) | Every removal changes the answer, and the answer must be reportable. Non-positive rates are flagged in a note; outliers are the analyst's call |
| A "confidence band on the fit" that pretends the model is correct | A prediction band from a wrong model is precise and wrong. The bootstrap band is on the *parameters* |
| Automatic model selection ("we chose the best model for you") | Model choice is the thing being taught. The package ranks by AICc and prints the Δ; the sentence is the student's |
| R² as a goodness-of-fit headline | R² rises when you add parameters and cannot fall when you add points. AICc is the default for comparison, and R² is printed with its limits |
| A GUI | The audience is learning to read output, not to click past it |

## Out of scope for this repository

Progress-curve (time-course) analysis, multi-substrate mechanisms, pH/temperature models,
molecular dynamics, and anything requiring a structural model. Those are their own 15-repo
entries.

## How to contribute

1. Any change to a number in the documentation must come with the command that produced it.
   `docs/validation.md` lists the checks; a pull request that adds a claim also adds the test
   or script that asserts it.
2. New datasets must be generated by `scripts/make_datasets.py` (deterministic, seeded),
   carry metadata with `synthetic: true`, the seed and the error model, and pass
   `check_data_metadata.py`.
3. New citations must resolve at Crossref with a matching title — `check_references.py` fails
   otherwise, and a DOI that resolves to the wrong paper is treated as a defect.
4. `mkdocs build --strict` must be clean: no warnings, no orphan pages, no broken links.

## Versioning

`kinetics` follows semantic versioning for the API. `0.1.x` fixes defects; `0.2.0` may add
models or arguments. Numbers in the documentation are tied to the committed datasets, so a
change to a dataset is a change to the documentation and is versioned accordingly.
